# Loadbearing Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Local web app: pick an architecture problem, draw a solution with typed components on a React Flow canvas (+ sticky notes/pen), get graded by a pluggable LLM with per-dimension rubric, twist rounds, and per-concept mastery tracking in SQLite.

**Architecture:** npm-workspaces monorepo — `client/` (Vite React TS, @xyflow/react, Zustand) talking REST to `server/` (Hono on Node, better-sqlite3). Server owns LLM keys/adapters, scoring prompts, problem bank, mastery math. Shared TS types duplicated in a `shared/` package.

**Tech Stack:** TypeScript everywhere, Vite 5, React 18, @xyflow/react 12, Zustand 4, Hono 4, better-sqlite3 11, Vitest 2, tsx (server dev).

## Global Constraints

- Windows dev box; all paths must work on win32; server binds 127.0.0.1 only.
- SQLite file at `data/loadbearing.sqlite` (gitignored), WAL mode.
- API keys never sent back to client after save (mask as `sk-...last4`).
- LLM payloads exclude node positions.
- Canvas draft autosave: single writer, debounced, one localStorage key per problem (`draft:<problemId>`) — no dual-write merging.
- Concept taxonomy is a fixed const list; mastery keys must come from it.
- Fake LLM mode via env `FAKE_LLM=1` for tests/dev without keys.
- Ports: client 5173 (Vite default), server 8787; Vite proxies `/api` → 8787.

### Task 2: LLM adapter layer

**Files:**
- Create: `server/src/llm/adapter.ts`, `server/src/llm/json.ts`
- Test: `server/src/llm/json.test.ts`, `server/src/llm/adapter.test.ts`

**Interfaces (Produces):**
- `type LlmConfig = { provider:'anthropic'|'openai-compatible'|'fake', baseUrl?:string, model:string, apiKey:string }`
- `complete(cfg: LlmConfig, system: string, user: string): Promise<string>` — raw text; anthropic → POST `https://api.anthropic.com/v1/messages` (headers `x-api-key`, `anthropic-version: 2023-06-01`, max_tokens 8000, reads `content[0].text`); openai-compatible → POST `${baseUrl}/chat/completions` (`Authorization: Bearer`, reads `choices[0].message.content`); fake → returns `globalThis.__FAKE_LLM_RESPONSE` (set by tests/dev route).
- `completeJson<T>(cfg, system, user): Promise<T>` — calls `complete`, then `extractJson`; on parse failure, ONE repair round: re-call with user message `"Your previous reply was not valid JSON. Reply with ONLY the corrected JSON. Previous reply: <raw>"`; throws `LlmJsonError(raw)` after second failure.
- `extractJson(text: string): unknown` in `json.ts` — strips ``` fences, finds first `{`..matching last `}`, `JSON.parse`.
- Typed errors: `LlmHttpError(status, providerHint)` — hints map: 401 → "check API key", 429 → "rate limited — wait or switch provider", 404 model → "model name wrong for this provider".

**Steps:**
- [ ] Failing tests for `extractJson`: plain JSON; fenced ```json; prose-wrapped JSON; trailing text; invalid → throws.
- [ ] Implement `json.ts`; tests PASS.
- [ ] Failing tests for `complete` with mocked `fetch` (vi.stubGlobal): anthropic request shape (url, headers, body.model, body.messages) and response extraction; openai-compatible shape; 401 → LlmHttpError with key hint; fake provider path.
- [ ] Implement `adapter.ts`; tests PASS. 60s AbortSignal timeout.
- [ ] Commit `feat: pluggable LLM adapters (anthropic, openai-compatible, fake)`.
